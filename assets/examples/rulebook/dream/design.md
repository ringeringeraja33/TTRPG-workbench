# Dream Archaeology: concept to playable proposal

Synthetic user input: "Make a game about excavating dreams. Memories can be exchanged for power. Investigation and changing identity should matter."

Retained commitments: dream archaeology, memory exchange, investigation and identity. Provisional choices: one GM and two players, one expedition of four scenes, low complexity, nonlethal consequences, one ordinary d6. These choices remain editable. The user has not approved them for a real project. Revision 0.2 is the fixture's tested prototype, not a published complete campaign system.

Design question: do you reveal evidence at the price of a personal memory, or preserve yourself and accept an incomplete reconstruction? A memory card's text matters to its owner; the player describes the loss without the GM deciding the character's beliefs. Trading cards lets another investigator pay the cost and take custody of its story. This is a narrative cost plus a finite bonus, not evidence that identity changes have been simulated psychologically.

Compared approaches: Fate-style reusable narrative resources add a broader refresh economy; Blades-style stress and resistance add an extra mitigation procedure. Both are useful references, but this prototype selects a direct, irrevocable per-expedition memory payment before one d6 roll. See [source decisions](../../../../references/rulebook-sources.md). Numerical thresholds are original proposals. No percentiles, class levels or existing branded system is presumed.

Targets to inspect: each character has a distinct strong approach; preserving memories remains legal; failure provides evidence with reduced context and an onward path; resource spending never creates more memories. No battle subsystem, death rolls, shops or spells: this cooperative archaeological expedition resolves opposition through the same action procedure. Tools grant fictional access, not numeric bonuses. Campaign economy and long-term memory replacement remain outside this minimum playable scope.

Canonical book map: R-create and R-memory in creation/resources; R-delve in action; R-support and R-strain in recovery; R-scene and R-grow in expedition resolution. Player sheet and quickstart bind these IDs in project.json. GM scenario is a separate artifact. The core has no secret-only prerequisites.

Revision ledger:

- 0.1 proposal let exchanged faded memories become fresh. Reproduction: A spends a memory, trades it to B, B trades it back; one fresh memory is gained without a scene reward. Fix 0.2 preserves identity and faded flag on transfer; test confirms the original cannot be spent again.
- 0.1 rest was unlimited without spending a turn. This erased all accumulated strain before every check. Fix 0.2 costs one of five scene actions and is once per character per scene, including at zero strain; test rejects a second rest atomically.
- 0.1 scene closure checked progress before consequences. Fix 0.2 resolves both, then evaluates the deadline. A recovered archive never cancels strain already earned. Rule, card, quickstart and trace use 0.2.

Actual test outcomes and exact probabilities are written by the replay tool. Open nonblocking design questions: is one-die variance desirable, is helping too expensive, and how should a second expedition replace memories? Do not silently invent permanent advancement beyond the specified one-expedition endpoint.
