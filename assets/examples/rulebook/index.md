# Rulebook authoring acceptance cases

All inputs, characters and scenarios here are invented for this skill. They contain no user drafts, copied commercial rules or real campaign secrets. The design decisions are proposals approved only within these test fixtures, not user canon.

| Entry | Usable result | Observable validation |
|---|---|---|
| [Concept only: Dream Archaeology](dream/design.md) | Original [minimum playable book](dream/rules.md), [two cards](dream/characters.md), [GM scenario](dream/scenario.md), [public quick reference](dream/quickstart.md) | [Twenty-turn narrative companion](dream/playthrough.md) and simulated player actions; all resource categories, failure continuation, growth and fresh-process recovery; exact action probabilities |
| [Scattered notes: Lantern Couriers](courier.md) | Note-to-chapter mapping, diceless creation and travel procedures, sample action and boundary | Preserves diceless play, keeps one currency name, reconciles action timing; complete two-route example |
| [Contradictory rules: Glass Engine](conflict.md) | Located conflict, corrected canonical rule/table/card/example, migration and revision record | Registered contradictions fail; repaired claims pass; dependent files reported; no implicit cross-version character conversion |

Run `python -X utf8 scripts/rulebook_demo.py --output <new-private-directory>` from the skill root. Run `python -X utf8 -m unittest discover -s scripts -p "test_rulebook*.py"` for adversarial tests. Trace output is private by default and includes GM scenario information. The public quick reference was authored separately, not generated by removing secret headings.

These are deterministic engineering and editorial cases. They do not certify a general prose-understanding engine, independent agent behavior, arbitrary rulebooks, strategy balance or long campaigns. Live-player testing is not required.
