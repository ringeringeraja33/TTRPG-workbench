# 角色创建、升级与核验

1. 固定系统版本、允许书目、等级/年龄/时代、创建方式、资源上限、房规和玩家概念。先保留原卡副本。没有玩家偏好时可生成完整建议角色，但标为建议并允许替换。
2. 按规则的依赖次序创建：基础数值 → 出身/职业/背景 → 技能/能力 → 装备 → 衍生数值 → 叙事牵挂。不同系统采用不同次序，不套统一 d20 表。
3. 建来源账：字段、基础值、加减来源、最终值、选项出处、是否已选。核验总预算、上限、重复熟练/专长、先决条件、法术已知与准备区别、施法资源、货币和负重。
4. 派生字段重新计算；自动表的缓存值和公式不等于正确。读取公式并核对输入单元格；不得宣称 openpyxl 执行了 Excel 公式。若需要精确版式或公式回算，使用可用文档/表格工具并实际验证。
5. 检查角色能参与模组、和其他角色有关联、有玩家可选择的动机；不得替玩家确定隐秘创伤或强制道德取向。
6. 升级需保留前后差异、获得条件、资源变化和未选项；只修改角色拥有的内容。

认证等级：全部必填规则与计算已核验 → “在指定规则配置下核验通过”；只验证属性 → “属性分配核验通过”；书目、先决条件或公式不明 → “草案，待核验字段如下”。完整角色卡需要覆盖该系统实际必填项，不能用核心字段样例冒充完整角色。

输出用 [创建核对表](../assets/templates/character.md)，非标准系统先读取其规则书和对应卡的创建步骤。陌生表格不要运行宏或外部链接。
