# 规则设计与创新

写清目标体验和可观察指标：例如每场冲突平均 3–5 轮、一次行动结算少于一分钟。先还原现有规则输入、随机变量、阈值、代价、效果与恢复频率，再修改一个可归因因素。

每条可执行规则包含：触发者/时点、前提、声明、支付时点、骰法与修正、成功/平手/失败、目标与范围、持续、叠加、重试、取消/退款、恢复。给最小例子和至少一个边界例子。

检查资源来源—消耗—上限—刷新闭环；检查无限重试、免费循环、行动外收益、多人叠加和最优策略挤压其他角色空间。叙事权限本身也是收益，不能只比较平均伤害。

概率分析区分独立重投、取高/低、共享个位的 CoC 奖励骰、爆骰、骰池及多级成功。阈值成功率不包含天然1/20等特例时必须说明。使用 `scripts/dice.py probability` 做精确枚举；复杂模型另写有种子模拟并报告样本数、误差和假设。

测试低/中/高能力、单次/连续遭遇、资源满/枯竭、合作/竞争等代表情境。与基线比较完成时间、死亡/退出风险、资源消耗、选择多样性和主持负担。概率正确不能证明体验平衡。

规则书建议骨架：玩法承诺与示例 → 核心结算 → 创建 → 行动/冲突 → 探索/社交 → 装备与能力 → 恢复成长 → GM 工具 → 完整实例 → 术语/索引。检查术语一致、规则先定义再引用、示例与公式一致、例外能定位。初稿允许留下明确的设计问题，禁止用“由主持决定”掩盖核心机制缺失。

输出采用 [规则提案模板](../assets/templates/rules-proposal.md)。兼容性声明限定到测试过的版本与内容；玩家确认采用后才写入战役房规。
