# 主持模式与会话恢复

## 模式

- 准备：可处理 GM 秘密，交付开团准备、场景速查、角色关联、规则索引和无剧透招募简介。
- 现场辅助：为人类 GM 给裁定选项、NPC 反应和状态提醒；用户保留最终裁定，不自动在玩家渠道发言。
- 直接主持：先确认开团必要配置；一次推进到一个需要玩家决定的节点，等待回应。选项只作示例，允许其他合理行动。

## 主持循环

场景锚点（时间/地点/可感知信息） → 玩家意图及方法 → 判断是否需骰 → 说明风险和已知代价 → 玩家确认/掷骰 → 按约定规则结算 → 只叙述可见后果 → 更新状态。无需检定时直接推进。隐藏检定按开团约定处理，记录真实骰与隐蔽原因。

玩家掷骰模式等待实际结果；工具模式执行骰具，保留表达式、原骰、修正、结果、时间和事件 ID。重试工具前检查事件是否已经结算；不为得到期望结果重投。数值例子写“测试输入”，不得作为现场随机结果。

NPC 根据目标、信息和资源行动；不要让全体 NPC 共享 GM 全知。对玩家聪明解决方案给对应效果。失败贯彻已预告风险，不能临时增加惩罚以强迫既定路线。

战斗记录轮次、顺序、位置/距离、行动资源、效果到期、伤害、撤离；探索记录游戏时间、光源/补给和遭遇触发；调查记录“世界事实、已发现证据、玩家推测”三个层次。具体单位和恢复以系统为准。

## 状态与秘密

战役目录由用户项目承载，通用技能不保存活跃档案。复制 [状态模板](../assets/templates/state.json)，GM 完整记录与 `player-summary.md` 分开保存。公开输出按字段白名单人工检查；不要先串行化全部 GM 对象再尝试删词。

同一对话/同一屏幕的玩家能够看到已输出的文字，标题折叠不能保密。需要保密时仅写 GM 文件，并确认该界面受众；向玩家提供独立摘要。记录中私密字段不能写进技能测试报告。

每个结算事件记录 before、after、依据和唯一 ID。每个重大场景结束/会话结束保存新快照；先读旧状态，写 UTF-8 临时文件、解析校验后替换目标，保留上一版本。发生并发编辑时比较 revision，冲突时合并已知事件，不能静默覆盖。

恢复时读取最新 GM 状态及玩家摘要，核对规则版本、revision、最后已结算事件、待掷骰、未付款资源和未决选择。从未完成节点继续，不能重复扣资源或掷骰。跨设备只读取用户指定同步副本；摘要缺项时询问，不能补写为既成事实。

使用 [交接模板](../assets/templates/handoff.md)。玩家可暂停、调整内容边界或纠正状态，必要时修订最近事件并标注原因。
