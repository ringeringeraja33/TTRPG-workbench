# 来源与检索

## 用户本地资料

优先使用用户当前指定资料库；未指定时读取技能目录的`local-paths.json`中的`library_root`。从资料库的`资料索引.md`或`索引/local-inventory.json`进入；配置中有`index_root`时以该目录为准。没有配置时，只在用户已指定的资料目录工作，不扫描无关个人目录。

资料清单、主题页码索引、核查记录与提取缓存统一保存在资料库的`索引`目录（或用户明确配置的`index_root`）。源码库、技能安装副本与个人资料索引分开；个人索引和全文缓存不纳入公开仓库。自动识别是候选信息，不能替代正文核查。历史清单不覆盖当前路径，未找到的旧文件单独保留状态，不自动恢复。

检索：先按文件名与清单缩小范围，再用 `scripts/library.py read` 读取目标章节。PDF 支持物理页锚点，DOCX 支持段落锚点，XLSX 支持工作表和单元格锚点，PPTX 支持幻灯片 XML 名称。CHM 需要可信只读解包工具；CHW 是辅助索引，不独立视为规则书。旧 DOC 需另存副本或可信读取器；图片和无文本 PDF 需 OCR，再目视核查数字与表格。无须为了规则检索重写源文件。

## 证据链

每条实质规则记录：系统、规则版本、书名/页面标题、发布者、文献性质、章节、PDF 页序、印刷页码、短释义、URL/本地路径、核查日期。引用原文时保持短小；完整正文留在原书。

解释优先采用已约定版本的规则正文及适用官方勘误，官方 FAQ 用来澄清。房规在当前桌上可覆盖正文，但输出必须标记覆盖点。第三方建议和译者注单列。版本较新不意味着适用于当前战役。遇到翻译冲突，定位原语言对应条文并说明差异。

输出规则答案：结论 → 触发条件与例外 → 一个情境例子 → 直接支持结论的来源。对困难查询区分“已确认”“由规则推导”“待查证”；现场可给明确的临时裁定，记录待复核项并沿用桌上已确认处理，避免反复停团。

## 参考来源与引用

完整的责任者、版本、链接、核查范围和来源编号见 [bibliography.md](bibliography.md)。引用格式和每次交付的参考清单见 [citation-guide.md](citation-guide.md)。网页暂不可用时保留核查失败状态；书目记录不能代替当前任务需要的正文。

只有在准备实际发布衍生作品时才按采用资料核对许可、署名和保留内容；免费可下载不等于可自由再分发。当前技能不附商业书全文，不对本地译本的传播许可作推定。

## 分类后定位

本地资料经过分类移动时，以用户清单的path字段为准；previous_path仅用于历史追溯。分系统参考中的书名是检索标识，不要求用户采用某种文件夹布局。
