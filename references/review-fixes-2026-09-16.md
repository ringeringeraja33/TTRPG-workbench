# 代码审查修复记录（2026-09-16）

本轮修复审查中确认的 12 个缺陷。完整架构、规则系统与产品功能仍有后续完善空间；本记录只声明已验证的修复范围。

| 编号 | 问题 | 修复与验证 |
|---|---|---|
| R01 | 默认状态读取泄漏私密检定历史 | 标准输出只含版本与主持人；完整个人状态显式写入 `--private-output`，读取不修改版本。 |
| R02 | 日志命令空白差异绕过私密输出 | 统一解析命令边界后再分派、判定受众；空格、制表符与全角前缀均覆盖。 |
| R03 | 私密先攻被后续列表公开 | 每条先攻保存受众快照，列表按查看者过滤并私密返回；关闭暗骰不扩大旧记录受众。 |
| R04 | 对抗结果向后手复制私密先手检定 | 仅当当前完整受众都有权限时复制先手明细，否则返回 `hidden: true`；公开对抗保留明细。 |
| R05 | 抽表禁用可被制表符绕过 | 功能开关与分派共用命令分类，拒绝操作不改变版本。 |
| R06 | 成长超过 100 后无法检定 | 两个检定入口与存储范围统一为整数 0–999；覆盖 100→104 后继续检定及边界拒绝。 |
| R07 | 清洁日志误删感叹号骰子表达式 | 日志保存命令类型，旧日志兼容四种前缀；骰子表达式及结果原样保留。 |
| R08 | DOCX 导出成功但 XML 损坏 | 创建文件前校验 XML；非法控制字符明确报错且不留下损坏文件，可使用 JSON 保留原文。 |
| R09 | 线索玩家投影带出 GM 字段 | 校验受众类型，只投影 `id` 与 `text`。 |
| R10 | 角色卡嵌套对象带出 GM 字段 | 递归白名单与字段类型校验，覆盖全部六份背景建卡示例。 |
| R11 | 发布标志与接收者类型混淆 | `released` 必须是布尔值，接收者必须是 ID 列表并精确匹配；非法清单拒绝发布。 |
| R12 | OCR 内容变化仍沿用旧核验状态 | 核验绑定原文件和完整单元内容、元数据的哈希；文本、提取方法、源文件变化或删除使其失效，原核验归档保留。 |

## 验证结果

- 169 项单元与回归测试通过，其中新增 14 项覆盖上述缺陷、旧核验迁移和未重建索引时的源文件变更。
- CoC 与 D&D 各 20 回合模拟回放通过，均在第 10 回合验证新进程恢复。
- 8 个 Keeper 情境验收通过。
- 能力清单生成检查通过。

复现命令见 [validation.md](validation.md)。这些检查使用合成数据和模拟流程，不代表真人桌测或全规则认证。

## 兼容性变化

- 默认读取 CLI 不再输出完整 `player`，需要它的本地调用方须使用 `--private-output`。
- `.init` 查询与修改回执通过私密输出取得。旧先攻没有受众标记时只向原所有者显示；不能从历史数据可靠推断其是否公开。
- 旧对抗记录没有受众标记时保守按原发起者私密处理。
- 旧资料核验缺少提取内容哈希时归档至 `review_history`，须重新核验后才显示有效状态。归档保留原备注，不删除历史证据。
- 新角色卡字段必须显式加入玩家字段 schema；未知嵌套字段不会自动发布。
- 本工具的 actor 是本地操作者提供的身份标签，不是登录认证。私密文件访问权限仍由本机操作者管理。
